# v0.3.C — 노티 액션 (완료/snooze) + 등록된 Note 시간 편집

**날짜:** 2026-06-04
**상태:** 디자인 승인 대기
**선행:** v0.3.A (PR #6), v0.3.B (PR #7) — 모두 master merged

## Goal

v0.3.A에서 의도적으로 미룬 polish 잔여 2항목 처리.

1. **노티 액션 버튼** — 알람 노티에 "완료" / "5분 뒤" 버튼. 완료는 Note에 `isCompleted` 상태 박음. Snooze는 5분 뒤 재발화.
2. **등록된 Note 시간 편집** — MemoDetail에서 datetime을 변경하면 시스템 캘린더 이벤트는 update(같은 ID 유지), 알람은 동일 requestId로 re-schedule.

## Background

v0.3.A에서 알람 발화/캘린더 등록까지는 완성됐으나 발화 후 행동(노티 액션) 및 발화 전 수정(시간 편집)이 비어 있었음. 출시 전 polish 마지막 두 항목.

## Architecture

| 모듈 | 변경 |
|---|---|
| `:local` | `AlarmReceiver`에 action 분기 (FIRE/DONE/SNOOZE). `CalendarWriter.updateEvent(eventId, draft): Boolean` 신설. `AlarmScheduler`는 무변경 (기존 schedule이 동일 requestId 시 자동 replace) |
| `:local`에 `NotificationActionsEntryPoint` (Hilt EntryPoint) | Receiver가 UseCase 가져오기 위한 진입점. v0.3.A의 `DeepLinkEntryPoint` 패턴. |
| `:repository` | `NoteEntity` v3 (+`isCompleted: Boolean`). Room migration `2→3`. `Note` domain +`isCompleted`. mapper 갱신 |
| `:usecase` | 신설 3종: `CompleteScheduledNoteUseCase`, `SnoozeReminderUseCase`, `RescheduleNoteUseCase` + Hilt `@Binds` |
| `:feature_memo` | `MemoDetailScreen`에 "시간 변경" 버튼 + DateTimePickerSheet 호출. 완료 표시 (제목 strikethrough + 체크 아이콘). `MemoDetailViewModel`에 `onComplete()`, `onReschedule(Instant)`. `MemoListScreen`도 완료 표시 |
| `:app` | DeepLinkRouter 무변경. `AlarmReceiver` 본문에 notification builder의 액션 2개 추가 |

추가 의존성/권한 없음.

## Components

### `:local/AlarmReceiver` — action 분기

```kotlin
class AlarmReceiver : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        val requestId = intent.getIntExtra(EXTRA_REQUEST_ID, -1)
        val noteId = intent.getLongExtra(EXTRA_NOTE_ID, -1L)
        when (intent.action) {
            ACTION_FIRE -> postNotification(context, intent, requestId, noteId)
            ACTION_DONE -> handleDone(context, requestId, noteId)
            ACTION_SNOOZE -> handleSnooze(context, requestId, noteId)
        }
    }

    private fun postNotification(...) {
        // 기존 NotificationCompat.Builder + addAction(완료) + addAction(5분 뒤)
    }

    private fun handleDone(context: Context, requestId: Int, noteId: Long) {
        val entry = EntryPointAccessors.fromApplication(
            context.applicationContext,
            NotificationActionsEntryPoint::class.java,
        )
        CoroutineScope(Dispatchers.IO).launch {
            entry.completeScheduledNote().invoke(noteId)
        }
        NotificationManagerCompat.from(context).cancel(requestId)
    }

    private fun handleSnooze(context: Context, requestId: Int, noteId: Long) {
        val entry = EntryPointAccessors.fromApplication(
            context.applicationContext,
            NotificationActionsEntryPoint::class.java,
        )
        CoroutineScope(Dispatchers.IO).launch {
            entry.snoozeReminder().invoke(noteId, SNOOZE_DELAY_MS)
        }
        NotificationManagerCompat.from(context).cancel(requestId)
    }

    companion object {
        const val ACTION_FIRE = "com.just.assistant.local.alarm.FIRE"
        const val ACTION_DONE = "com.just.assistant.local.alarm.DONE"
        const val ACTION_SNOOZE = "com.just.assistant.local.alarm.SNOOZE"
        const val ACTION_VIEW_NOTE = "com.just.assistant.local.alarm.VIEW_NOTE"
        const val EXTRA_TITLE = "extra.title"
        const val EXTRA_BODY = "extra.body"
        const val EXTRA_REQUEST_ID = "extra.requestId"
        const val EXTRA_NOTE_ID = "extra.noteId"
        const val SNOOZE_DELAY_MS = 5 * 60 * 1000L
    }
}
```

    val uri = ContentUris.withAppendedId(CalendarContract.Events.CONTENT_URI, eventId)

### `:usecase` 신설 3종

**`CompleteScheduledNoteUseCase`**:

```kotlin
interface CompleteScheduledNoteUseCase {
    suspend operator fun invoke(noteId: Long)
}

class CompleteScheduledNoteUseCaseImpl @Inject constructor(
    private val noteRepository: NoteRepository,
    private val unschedule: UnscheduleNoteUseCase,
) : CompleteScheduledNoteUseCase {
    override suspend fun invoke(noteId: Long) {
        unschedule(noteId)  // alarmRequestId/calendarEventId 비움
        val note = noteRepository.findById(noteId) ?: return
        if (note.isCompleted) return
        noteRepository.save(note.copy(isCompleted = true))
    }
}
```

**`SnoozeReminderUseCase`**:

```kotlin
interface SnoozeReminderUseCase {
    suspend operator fun invoke(noteId: Long, delayMs: Long)
}

class SnoozeReminderUseCaseImpl @Inject constructor(
    private val noteRepository: NoteRepository,
    private val alarmScheduler: AlarmScheduler,
) : SnoozeReminderUseCase {
    override suspend fun invoke(noteId: Long, delayMs: Long) {
        val note = noteRepository.findById(noteId) ?: return
        val requestId = note.alarmRequestId ?: return
        alarmScheduler.schedule(
            requestId = requestId,
            whenEpochMs = System.currentTimeMillis() + delayMs,
            title = note.title,
            body = note.body,
            noteId = noteId,
        )
    }
}
```

**`RescheduleNoteUseCase`**:

```kotlin
interface RescheduleNoteUseCase {
    suspend operator fun invoke(noteId: Long, newDateTime: Instant)
}

class RescheduleNoteUseCaseImpl @Inject constructor(
    private val noteRepository: NoteRepository,
    private val calendarWriter: CalendarWriter,
    private val alarmScheduler: AlarmScheduler,
) : RescheduleNoteUseCase {
    override suspend fun invoke(noteId: Long, newDateTime: Instant) {
        val note = noteRepository.findById(noteId) ?: return
        note.calendarEventId?.let { eventId ->
            val start = newDateTime.toEpochMilli()
            val end = start + 60 * 60 * 1000L  // 1시간 기본
            calendarWriter.updateEvent(
                eventId,
                CalendarEventDraft(
                    title = note.title,
                    description = note.body,
                    startEpochMs = start,
                    endEpochMs = end,
                ),
            )
        }
        note.alarmRequestId?.let { requestId ->
            alarmScheduler.schedule(
                requestId = requestId,
                whenEpochMs = newDateTime.toEpochMilli(),
                title = note.title,
                body = note.body,
                noteId = noteId,
            )
        }
        noteRepository.save(
            note.copy(datetime = newDateTime, updatedAt = Instant.now()),
        )
    }
}
```

## Data Flow

### 1. 노티 '완료' 탭
```
NotificationCompat addAction("완료", donePending)
사용자 탭 → BroadcastReceiver
  → AlarmReceiver.onReceive(action=ACTION_DONE, noteId, requestId)
  → EntryPointAccessors → CompleteScheduledNoteUseCase
     → UnscheduleNote(noteId): cancel alarm + null refs
     → save(note.copy(isCompleted=true))
  → NotificationManagerCompat.cancel(requestId)
사용자가 MemoDetail 방문 시 → strikethrough + 체크 표시
```

### 2. 노티 'Snooze' 탭
```
사용자 탭 → AlarmReceiver(ACTION_SNOOZE, noteId, requestId)
  → SnoozeReminderUseCase(noteId, 5분)
     → findById → AlarmScheduler.schedule(requestId, now+5min, title, body, noteId)
  → NotificationManagerCompat.cancel(requestId)
5분 뒤 → AlarmManager → AlarmReceiver(ACTION_FIRE) → 새 노티
```

### 3. MemoDetail '시간 변경'
```
"시간 변경" 버튼 탭
  → DateTimePickerSheet (v0.3.A의 것 재사용)
  → onConfirm(newDateTime)
  → viewModel.onReschedule(newDateTime)
  → RescheduleNoteUseCase(noteId, newDateTime)
     → EVENT: CalendarWriter.updateEvent(calendarEventId, draft)
     → REMINDER: AlarmScheduler.schedule(alarmRequestId, newDateTime, ..., noteId)
     → save(note.copy(datetime=newDateTime, updatedAt=now))
  → load() → state 갱신
Toast: "시간이 변경됨"
```

## Permissions

추가 권한 없음. v0.3.A에서 보유한 `READ/WRITE_CALENDAR`, `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM` 그대로.

## Error handling

- `findById` null → no-op
- 이미 `isCompleted = true` 인 Note → idempotent skip
- `CalendarWriter.updateEvent`가 0 rows (캘린더에서 이미 삭제) → Note datetime만 갱신, 사용자 알림 X
- `Note.alarmRequestId == null`에 snooze 호출 → no-op
- 시간 편집 후 새 datetime이 과거 시점 → AlarmManager가 즉시 발화. 의도된 동작.
