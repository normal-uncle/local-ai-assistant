# v0.3.E — 음성 캡처 (STT → 텍스트 분류)

**날짜:** 2026-06-05 (STT로 재설계: 2026-06-08)
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v0.3.A~D (PR #6/#7/#8/#9) 모두 master merged

## Goal

음성 입력을 도입해 멀티모달 입력(텍스트·이미지·음성)을 완성한다. **Android 시스템 음성인식(STT)**으로 발화를 텍스트로 변환해 **기존 텍스트 분류 경로**(`ClassifyCaptureUseCase`)에 흘려보낸다. 변환된 텍스트는 입력 필드에 채워져 사용자가 검토·수정 후 기존 "준비"로 분류한다.

## Background

- 원래 v0.3.E는 **Gemma audio 직접 분류**로 시도했으나, gating spike에서 현재 `gemma-4-E2B-it.litertlm`이 **audio 가중치를 포함하지 않음**을 확인(WAV·float32 형식 모두 `audioBackend` 설정에도 13분+ 정지 + 기기 wedge). audio 되는 모델은 공식 `google/gemma-3n-*`뿐이나 **gated**(런타임 공개 URL 다운로드와 충돌) + 베이스 모델 전면 교체 비용. → **STT 경로로 선회**(원래 v0.1 설계안이기도 함).
- STT는 음성을 텍스트로만 바꾸므로 **AI/usecase/모델 레이어는 무변경**. 기존 텍스트 분류가 그대로 처리.
- Gemma audio 관련으로 잠시 추가했던 코드(`generate(prompt, images, audio)` 오버로드, `InferenceConfig.enableAudio`)는 dead code가 되어 **revert**함(master 상태로 복귀).

## Architecture

| 모듈 | 변경 |
|---|---|
| `feature_capture` | `CaptureScreen`에 음성 입력 버튼. 시스템 음성인식 인텐트(`RecognizerIntent.ACTION_RECOGNIZE_SPEECH`, `EXTRA_PREFER_OFFLINE`) 실행 → 결과 transcript를 입력 필드에 채움(`viewModel.onInputChanged`). 인식 앱 없으면 Toast. strings 추가 |
| 그 외 | 변경 없음 (`:ai`/`:usecase`/`:local`/`:repository`/`:app` 무변경) |

추가 의존성·권한 없음(시스템 인텐트가 마이크를 처리하므로 앱에 `RECORD_AUDIO` 불필요). DB·메모 화면 변경 없음.

## Components

### `feature_capture/CaptureScreen` — 음성 입력 버튼

```kotlin
val context = LocalContext.current
val voiceUnavailable = stringResource(R.string.capture_voice_unavailable)
val voicePrompt = stringResource(R.string.capture_voice_prompt)
val speechLauncher =
    rememberLauncherForActivityResult(ActivityResultContracts.StartActivityForResult()) { result ->
        val transcript =
            result.data
                ?.getStringArrayListExtra(RecognizerIntent.EXTRA_RESULTS)
                ?.firstOrNull()
                ?.trim()
        if (!transcript.isNullOrEmpty()) {
            val current = state.input.trim()
            viewModel.onInputChanged(if (current.isEmpty()) transcript else "$current $transcript")
        }
    }

fun launchSpeech() {
    val intent =
        Intent(RecognizerIntent.ACTION_RECOGNIZE_SPEECH).apply {
            putExtra(RecognizerIntent.EXTRA_LANGUAGE_MODEL, RecognizerIntent.LANGUAGE_MODEL_FREE_FORM)
            putExtra(RecognizerIntent.EXTRA_PREFER_OFFLINE, true)
            putExtra(RecognizerIntent.EXTRA_LANGUAGE, java.util.Locale.getDefault())
            putExtra(RecognizerIntent.EXTRA_PROMPT, voicePrompt)
        }
    try {
        speechLauncher.launch(intent)
    } catch (e: android.content.ActivityNotFoundException) {
        Toast.makeText(context, voiceUnavailable, Toast.LENGTH_SHORT).show()
    }
}
```

음성 버튼은 기존 이미지 소스(갤러리/카메라) Row에 합류해 세 번째 버튼으로 배치. 탭 시 `launchSpeech()`.

- transcript는 입력 필드에 **추가**(기존 텍스트 있으면 공백으로 이어붙임) → 사용자가 검토·수정 후 기존 "준비" 버튼으로 분류(기존 `onPrepare()` 경로 재사용).
- `EXTRA_PREFER_OFFLINE = true`로 온디바이스 우선(프라이버시·오프라인 컨셉 부합). 미지원 기기는 시스템이 온라인으로 폴백.

### 변경 없는 부분
- `CaptureViewModel`: 기존 `onInputChanged` / `onPrepare` 재사용. 생성자·상태 변경 없음.
- `:ai`/`:usecase`/모델/DB: 무변경.

## Data Flow

```
[Capture 화면] 음성 버튼 → RecognizerIntent.ACTION_RECOGNIZE_SPEECH (시스템 마이크 UI)
  → 결과 transcript → viewModel.onInputChanged(입력에 추가)
  → 사용자 검토/수정 → "준비" → 기존 ClassifyCaptureUseCase(text) → PreviewSheet → 저장
인식 앱 없음(ActivityNotFoundException) → Toast 안내
```

## Permissions

추가 권한 없음. 시스템 음성인식 액티비티가 `RECORD_AUDIO`를 자체 처리.

## Error handling

- 음성인식 앱 미설치/미지원 → `ActivityNotFoundException` → Toast(`capture_voice_unavailable`).
- 인식 취소/무음 → 결과 transcript null/빈 문자열 → 입력 변경 없음(no-op).
- 분류·저장은 기존 텍스트 경로의 에러 처리 그대로.

## Testing

- **Compose UI 테스트**(`CaptureScreenTest`): 음성 버튼이 표시되는지 정도(인텐트 결과는 시스템 의존이라 단위 테스트 어려움 — 버튼 존재/클릭 가능 확인). 기존 텍스트 입력→준비 흐름은 기존 테스트 유지.
- **디바이스 smoke**: 음성 버튼 → "내일 오후 세시 치과" 발화 → 입력 필드에 텍스트 채워짐 → 준비 → EVENT + datetime. 인식 앱 없는 환경에서 Toast.
- AI/usecase 무변경이므로 해당 모듈 회귀 테스트는 기존 그대로 PASS.
