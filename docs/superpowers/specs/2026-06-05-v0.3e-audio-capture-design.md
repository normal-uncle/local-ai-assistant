# v0.3.E — 음성(오디오) 캡처 (녹음 → Gemma audio 분류)

**날짜:** 2026-06-05
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v0.3.A~D (PR #6/#7/#8/#9) 모두 master merged

## Goal

멀티모달 입력의 마지막 축인 **음성**을 도입한다. 사용자가 앱에서 마이크로 녹음한 음성을 **Gemma audio로 직접** 분류(MEMO/EVENT/REMINDER)한다. 녹음은 분류용 일회성으로만 쓰고 저장하지 않는다(저장·재생 없음). 이로써 텍스트·이미지·음성 3종 입력이 완성된다.

## Background

- v0.1 설계는 음성을 Android SpeechRecognizer(STT)→텍스트로 처리하려 했고 Gemma audio 직접 입력은 발열·배터리·부하를 이유로 v0.3+로 미뤘다. 실제로 STT는 끝내 구현되지 않았다(코드베이스에 SpeechRecognizer/녹음 없음). v0.3.E가 첫 음성 입력이다.
- 사용자 결정: **STT가 아니라 Gemma audio 직접**(멀티모달 완성).
- SDK 확인: `Content.AudioBytes(ByteArray)`, `Content.AudioFile`, `InputData.Audio` 존재. `EngineConfig`에 `audioBackend: Backend` 파라미터 존재(0.12.0). vision은 v0.3.D에서 `visionBackend`+`maxNumImages` 설정으로 동작 확인됨 — audio도 `audioBackend` 설정이 필요할 것으로 보인다.
- **미확인 리스크 2가지**:
  1. 이 `gemma-4-E2B-it.litertlm` 변환본이 **audio 인코더 가중치를 포함**하는지(vision은 됐으나 audio는 별개). `audioBackend`는 SDK 레벨 지원일 뿐 모델 파일 포함 여부는 다름.
  2. `Content.AudioBytes`가 받는 **정확한 바이트 형식**(WAV 헤더 포함 vs raw PCM16 vs float32 [-1,1]). Gemma audio 문서는 "mono 16kHz float32 [-1,1]"를 권장하나 SDK가 내부 디코드/변환을 하는지 불명.
- 따라서 v0.3.D처럼 **feasibility spike를 첫 단계(gating)** 로 둔다.

## Architecture

핵심 결정: `InferenceEngine.generate`를 **단일 `generate(prompt, images, audio)` 추상 + default 오버로드**로 확장한다(안 A). 기존 텍스트(`generate(prompt)`)·이미지(`generate(prompt, images)`) 호출부는 default 위임으로 무영향. SDK의 멀티모달 `Contents`(image+audio+text 통합) 모델과 정합.

| 모듈 | 변경 |
|---|---|
| `:ai` | `generate(prompt, images, audio: List<ByteArray>)` 추상화 + 1·2인자 default. LiteRtLm이 `Contents.of(images.map{ImageBytes} + audio.map{AudioBytes} + Text(prompt))` 전송. `InferenceConfig.enableAudio` → `EngineConfig.copy(audioBackend = Backend.CPU())`. `AudioClassificationPrompt` 신설 |
| `:local` | `AudioRecorder` 신설 — `AudioRecord`로 16kHz mono PCM 캡처 → spike가 확정한 형식의 ByteArray 반환. 저장 안 함(일회성) |
| `:usecase` | `ClassifyAudioCaptureUseCase(audioBytes)` 신설 + `@Binds` — 엔진을 `enableAudio=true`로 로드 |
| `feature_capture` | 마이크 버튼 + 녹음 상태 UI, RECORD_AUDIO 권한, `onPrepareAudio()`. 기존 PreviewSheet 재사용 |
| `:app` | manifest `RECORD_AUDIO` 권한. **DB·메모 화면 변경 없음** |

추가 의존성 없음. NoteEntity/Room 변경 없음(오디오 미저장).

## Phase 0 — Feasibility Spike (gating)

**별도 위치: `:app` androidTest**(모델이 `com.just.assistant` 샌드박스에 있어 :ai 테스트 컨텍스트에서 접근 불가 — v0.3.D와 동일 이유). 통과 전 본 구현 진입 금지.

- 픽스처: 호스트에서 macOS `say -o /tmp/spike.aiff "내일 오후 세시 회의 강남"` → `afconvert`/`ffmpeg`로 **16kHz mono WAV(PCM16)** 변환 → `app/src/androidTest/assets/spike/voice_16k_mono.wav`로 둔다. (spike가 raw/float32도 시도할 수 있게 변환 변형을 준비.)
- 테스트: 모델 로드(`InferenceConfig(enableAudio = true, preferGpu = false)`) → `engine.generate(prompt = "이 음성에서 들리는 말을 그대로 적어주세요.", images = emptyList(), audio = listOf(wavBytes))` → 응답이 발화 토큰("회의"/"3"/"세시"/"강남") 중 하나 이상 포함하는지 assert.
- **바이트 형식 확정**: 먼저 WAV 파일 바이트를 그대로 `AudioBytes`에 넣어 본다. 실패(정지/예외/무관 응답)하면 raw PCM16, 그 다음 float32 [-1,1] 변형을 시도해 어떤 형식이 동작하는지 로그로 기록. 동작 형식을 `AudioRecorder` 구현에 반영.

**판정:**
- 통과(예외 없음 + 응답이 발화 반영) → 동작 형식 확정 후 본 구현.
- 실패(audio 가중치 부재 의심: 어떤 형식도 정지/무관 응답) → 중단·보고. STT 폴백 선회 또는 v0.3.E 보류를 그때 결정.

> v0.3.D 교훈: spike 무한 정지 시 기기 logd가 wedge될 수 있음 → 시간 제한 실행 + 결과는 logcat으로 확인. connectedAndroidTest는 끝나며 앱을 언인스톨해 모델(filesDir)을 지움 → spike 후 모델 재다운로드/재푸시 필요.

## Components

### `:ai/InferenceEngine` — 오디오 포함 오버로드

```kotlin
interface InferenceEngine {
    suspend fun load(modelFile: File, config: InferenceConfig = InferenceConfig())
    fun unload()
    fun isReady(): Boolean

    /** 텍스트 전용. */
    suspend fun generate(prompt: String): String = generate(prompt, emptyList(), emptyList())

    /** 텍스트+이미지 (v0.3.D 호환). */
    suspend fun generate(prompt: String, images: List<ByteArray>): String =
        generate(prompt, images, emptyList())

    /** 멀티모달. images/audio 비었으면 해당 모달 생략. */
    suspend fun generate(prompt: String, images: List<ByteArray>, audio: List<ByteArray>): String

    val lastBackend: String? get() = null
}
```

### `:ai/LiteRtLmInferenceEngine`

`generate(prompt, images, audio)` 구현:

```kotlin
override suspend fun generate(
    prompt: String,
    images: List<ByteArray>,
    audio: List<ByteArray>,
): String = withContext(Dispatchers.IO) {
    val e = engine ?: error("InferenceEngine not loaded; call load() first")
    val cfg = currentConfig ?: error("InferenceEngine not loaded; call load() first")
    val samplerConfig = SamplerConfig(/* 기존 */)
    val conversationConfig = ConversationConfig(/* 기존 */)
    e.createConversation(conversationConfig).use { conversation ->
        val response =
            if (images.isEmpty() && audio.isEmpty()) {
                conversation.sendMessage(prompt)
            } else {
                val parts =
                    images.map { Content.ImageBytes(it) } +
                        audio.map { Content.AudioBytes(it) } +
                        Content.Text(prompt)
                conversation.sendMessage(Contents.of(parts))
            }
        response.contents.contents
            .filterIsInstance<Content.Text>()
            .joinToString(separator = "") { it.text }
    }
}
```

`load()`의 EngineConfig 구성에 audio 분기 추가(기존 vision 분기와 병렬):

```kotlin
val textConfig = EngineConfig(modelPath = ..., backend = Backend.CPU(), maxNumTokens = config.maxTokens, cacheDir = ...)
val baseConfig = textConfig.copy(
    visionBackend = if (config.enableVision) Backend.CPU() else textConfig.visionBackend,
    maxNumImages = if (config.enableVision) 1 else textConfig.maxNumImages,
    audioBackend = if (config.enableAudio) Backend.CPU() else textConfig.audioBackend,
)
```

> 기존 vision-only `copy(visionBackend=..., maxNumImages=1)`를 위 통합 형태로 일반화. enableVision/enableAudio 둘 다 false면 textConfig와 동일.

### `:local/audio/AudioRecorder`

```kotlin
interface AudioRecorder {
    fun start()
    /** 녹음 종료 후 분류용 오디오 바이트(spike가 확정한 형식) 반환. */
    fun stop(): ByteArray
    fun isRecording(): Boolean
}
```

- `AudioRecord(MediaRecorder.AudioSource.MIC, 16000, CHANNEL_IN_MONO, ENCODING_PCM_16BIT, ...)`로 PCM16 캡처.
- `stop()`에서 spike가 확정한 형식으로 변환(WAV 헤더 부착 또는 float32 변환). 형식은 spike 결과로 결정.
- 일회성: 파일 저장 없음. 큰 버퍼는 메모리 보관(짧은 메모 가정). 매우 길면 토큰 한계(아래 에러처리).

### `:usecase/ClassifyAudioCaptureUseCase`

```kotlin
interface ClassifyAudioCaptureUseCase {
    suspend operator fun invoke(audioBytes: ByteArray): ClassificationResult?
}

class ClassifyAudioCaptureUseCaseImpl @Inject constructor(
    private val engine: InferenceEngine,
    private val fileStore: ModelFileStore,
    private val prefs: ModelStatusPrefs,
) : ClassifyAudioCaptureUseCase {
    override suspend fun invoke(audioBytes: ByteArray): ClassificationResult? {
        val variantId = prefs.selectedVariantId.first() ?: return null
        val modelFile = fileStore.fileFor(variantId).takeIf { it.exists() } ?: return null
        return try {
            // enableAudio=true 로 로드 (audioBackend 미초기화 시 정지 — v0.3.D vision 교훈).
            // isReady() 가드 없이 매번 load (내부 dedup).
            engine.load(modelFile, InferenceConfig(enableAudio = true))
            val response = engine.generate(
                prompt = AudioClassificationPrompt.build(),
                images = emptyList(),
                audio = listOf(audioBytes),
            )
            ClassificationResult.parse(response)
        } catch (t: Throwable) {
            null
        }
    }
}
```

### `feature_capture/CaptureViewModel` + `CaptureScreen`

`CaptureState`에 `isRecording: Boolean` 추가. ViewModel:

```kotlin
fun onToggleRecord() {
    if (audioRecorder.isRecording()) {
        val bytes = audioRecorder.stop()
        _state.update { it.copy(isRecording = false, isPreparing = true) }
        viewModelScope.launch {
            val aiResult = classifyAudio(bytes)
            val preview = aiResult?.toPreview() ?: fallbackPreview("")  // 빈 입력 폴백
            _state.update { it.copy(preview = preview, isPreparing = false) }
        }

        audioRecorder.start()
        _state.update { it.copy(isRecording = true) }
    }
}
```

## Data Flow

```
[Capture 화면] 마이크 버튼 → (RECORD_AUDIO 권한) → AudioRecorder.start() (녹음중 표시)
  → 다시 탭 → AudioRecorder.stop() → 오디오 바이트(16kHz mono, spike 확정 형식)
  → ClassifyAudioCaptureUseCase(bytes)
     → engine.load(enableAudio=true) → generate(AudioClassificationPrompt, audio=[bytes])
     → ClassificationResult.parse
  → PreviewSheet (분류 결과, 사용자 수정 가능)
  → confirm → 기존 저장/스케줄 경로 (오디오는 저장 안 함)
```

## Permissions

| 권한 | 용도 | 처리 |
|---|---|---|
| `RECORD_AUDIO` | 마이크 녹음 | 마이크 버튼 탭 시 런타임 요청. 거부 시 Toast 안내 |

기존 권한 그대로. 오디오 미저장이라 저장소 권한 불필요.

## Error handling

- 모델 미준비/추론 실패/파싱 실패 → null → MEMO 폴백(빈 제목, 사용자 작성).
- RECORD_AUDIO 거부 → Toast, 녹음 미시작.
- **매우 긴 녹음** → 오디오 토큰이 `maxNumTokens=4096`을 초과하면 prefill 실패(문서화된 하드 제약, [[project-litertlm-gemma4-config]]) → 추론 예외 → MEMO 폴백. 길이 상한은 강제하지 않음(사용자 결정). 발열·지연도 길이에 비례하므로 짧은 메모 권장(UI 힌트 가능, 선택).
- 녹음 중 화면 이탈/프로세스 종료 → 진행 중 버퍼 폐기(일회성).
