# v0.3.B — GPU backend 시도 + ClassificationPrompt rules 강화

**날짜:** 2026-06-02
**상태:** 디자인 승인 대기
**선행:** v0.3.A (PR #6) master merge 완료

## Goal

v0.2/v0.3.A에서 측정된 baseline (typeAcc 0.72, dtAcc 0.78, p50 14.7s, p95 16.3s, Galaxy Z Fold4 SD8G1 CPU 4t)을 두 축에서 개선 시도:

1. **속도** — `Backend.GPU()`로 init 시도, 실패 시 자동 CPU fallback (사용자 영향 0)
2. **정확도** — `ClassificationPrompt`의 rules 섹션에 동사형 = REMINDER, 시각 없어도 일정 표현 = EVENT 명시

성공 기준은 **상대 개선 확인**만 — 측정 후 PR 본문에 비교 표.

## Background

v0.2 회귀에서 오분류 14건 패턴:
- REMINDER → MEMO 8건: "우유 사오기", "택배 받기", "buy milk" 등 동사형/명령형
- EVENT → MEMO 4건: "이번주 토요일 등산", "수요일 점심 약속" 등 시각 없는 일정
- 기타 2건: 모호/이중 의도

이 14건이 v0.3.B의 primary target. 새 룰은 한국어/영어 양쪽 패턴을 명시.

GPU backend는 LiteRT-LM 0.12.0이 지원하지만 디바이스/모델 호환성이 v0.2/v0.3.A에서도 까다로웠던 전적이 있다 (CPU만 검증). 시도해서 init 실패하면 silent CPU fallback.

## Architecture

| 모듈 | 변경 |
|---|---|
| `:ai/inference/InferenceEngine` | interface에 `val lastBackend: String?` getter 추가 |
| `:ai/inference/LiteRtLmInferenceEngine` | `load()`에서 `Backend.GPU()` 먼저 시도 → catch → `Backend.CPU()` retry. `lastBackend` 갱신 |
| `:ai/prompt/ClassificationPrompt` | rules 섹션에 동사형/명령형 = REMINDER, 시각 없는 일정 표현 = EVENT 한국어/영어 명시 |
| `:ai/src/test/.../ClassificationPromptTest` (신설) | 새 rules가 build() 출력에 포함되는지 contains assert |
| `:app/regression/ClassificationRegressionTest` | report.json에 `backend: String` 필드 추가, `engine.lastBackend` 기록 |

`:repository`, `:usecase`, `:feature_*`, `:local`, `:app` (regression 외) — 무변경.

## Components

### `InferenceEngine` interface (extension)

```kotlin
interface InferenceEngine {
    suspend fun load(modelFile: File, config: InferenceConfig)
    fun unload()
    fun isReady(): Boolean
    suspend fun generate(prompt: String): String
    val lastBackend: String?
}
```

기본값은 `null` (load 전). load 성공 후 `"GPU"` 또는 `"CPU(fallback)"` 또는 `"CPU"` 중 하나.

### `LiteRtLmInferenceEngine.load` (새 흐름)

```kotlin
override suspend fun load(modelFile: File, config: InferenceConfig) {
    withContext(Dispatchers.IO) {
        if (engine != null && currentConfig == config && currentModelPath == modelFile.absolutePath) {
            return@withContext
        }
        engine?.close()
        engine = null

        val (newEngine, backend) = tryLoadWithFallback(modelFile, config)
        engine = newEngine
        currentConfig = config
        currentModelPath = modelFile.absolutePath
        _lastBackend = backend
    }
}

private fun tryLoadWithFallback(modelFile: File, config: InferenceConfig): Pair<Engine, String> {
    val gpuConfig = EngineConfig(
        modelPath = modelFile.absolutePath,
        backend = Backend.GPU(),
        maxNumTokens = config.maxTokens,
        cacheDir = context.cacheDir.absolutePath,
    )
    return try {
        val gpuEngine = Engine(gpuConfig).also { it.initialize() }
        gpuEngine to "GPU"
    } catch (e: Throwable) {
        Log.w(TAG, "GPU init failed, falling back to CPU", e)
        val cpuConfig = gpuConfig.copy(backend = Backend.CPU())
        val cpuEngine = Engine(cpuConfig).also { it.initialize() }
        cpuEngine to "CPU(fallback)"
    }
}
```

`Backend.CPU()`만 직접 호출하는 경로(예: 추후 사용자가 명시적으로 CPU 강제하는 옵션)는 v0.3.B 범위 밖.

### `ClassificationPrompt.build()` rules 강화

기존 rules 4줄 + 2줄 추가 (정확한 한국어/영어 표현은 plan에서 확정):

```
규칙:
- "내일 3시 치과", "다음주 월요일 회의" 같이 특정 시각이 있으면 EVENT.
- 시각이 명시되지 않아도 미래 사건/일정/약속 표현(요일·날짜 단어, 등산·모임·식사 등)은 EVENT.
- "콜백 잊지 말기", "퇴근 전 보고서 제출" 같이 마감/할 일이면 REMINDER.
- 동사형·명령형 동작/할 일(예: "~사오기", "~받기", "~제출", "buy", "pick up", "call", "register")은 시각이 없어도 REMINDER.
- 그 외 일반 메모/생각/정보는 MEMO.
- datetime_iso는 입력에 명확한 날짜·시간이 있을 때만 채우고, 없으면 null.
- tags는 입력에 자연스럽게 포함된 키워드. 강제로 만들지 말 것.
```

### Regression report 확장

`ClassificationRegressionTest`의 `Report` data class에 한 필드:

private data class Report(

리포트 작성 시 `engine.lastBackend ?: "unknown"` 박는다.

## Data Flow

```
앱 부팅 → ModelRepository.downloadSelected() 또는 이미 있음
  → AiModule 통해 LiteRtLmInferenceEngine 인스턴스 (Hilt @Singleton)

첫 분류 시 (ClassifyCaptureUseCase):
  → engine.load(modelFile, config)
     ├─ GPU init 시도
     │   ├─ 성공 → lastBackend = "GPU"
     │   └─ 실패 → CPU init → lastBackend = "CPU(fallback)"
     └─ engine 준비
  → engine.generate(ClassificationPrompt.build(input))

회귀:
  → engine.load() 후 50 case loop
  → 최종 report.json에 backend 필드 + 50 case 결과
```

## Error handling

- **GPU init throws** → `Log.w` + CPU retry. 사용자 영향 없음 (latency만 차이).
- **CPU init도 throws** → 예외 그대로 throw. 현재 동작 유지 (사용자에게 모델 로드 실패 안내).
- **Prompt 변경** → 런타임 검증 없음. 부작용 없음. 단순 string 변경.
- **lastBackend null 상태에서 generate 호출** → 가능성 없음 (`generate`는 `load` 후에만 호출 가능). 회귀 report에서 `engine.lastBackend ?: "unknown"` 방어.
