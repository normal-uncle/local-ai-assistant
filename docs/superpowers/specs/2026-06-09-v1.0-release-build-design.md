# v1.0-release — 릴리스 빌드 (R8 + 서명 골격)

**날짜:** 2026-06-09
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v1.0-icon까지 master merged. (v1.0 출시 준비 sub-project 4)

## Goal

출시용 release 빌드를 구성한다: **R8 코드/리소스 축소** + 안전한 keep 규칙 + **서명 설정 골격**(실제 keystore는 사용자가 추후 주입). versionName 0.1.0 유지.

## Scope / 비목표
- 범위: `:app` release buildType R8 활성, `proguard-rules.pro` keep 규칙, `keystore.properties` 기반 서명 골격(부재 시 unsigned), gitignore 보강.
- 비목표: 실제 keystore 생성·서명(사용자/시크릿), AAB·Play 업로드, Crashlytics, versionCode 자동 증가, 다른 모듈 변경.

## Background
- 현재 `:app` release: `isMinifyEnabled = false`, `proguardFiles(... , "proguard-rules.pro")` 참조하나 **`proguard-rules.pro` 파일 없음**.
- `@Serializable` 클래스: NavKey 라우트(`AssistantRoute`/`SettingsSubRoute`/`MemoSubRoute`), 원격 DTO(`CatalogDto`/`VariantDto`), ai(`ClassificationResult`/`ClassificationGoldenCase`). kotlinx-serialization 사용 — R8에서 생성 serializer 보존 필요.
- LiteRT-LM(`com.google.ai.edge.litertlm`)은 JNI 기반 — R8 strip 위험, 보존 권장.
- Hilt/Room/Compose/Retrofit/OkHttp는 자체 consumer R8 규칙 동봉(수동 keep 불필요).
- gitignore에 `local.properties`/`*.keystore`/`*.jks` 이미 포함. `keystore.properties`는 미포함 → 추가.

## Architecture

`app/build.gradle.kts`:
- 스크립트 상단에서 `keystore.properties`(루트) 존재 시 로드.
- `android { signingConfigs { create("release") { ... } } }` — 프로퍼티 있을 때만 storeFile/비번/alias 설정.
- `buildTypes.release`: `isMinifyEnabled = true`, `isShrinkResources = true`, 그리고 keystore.properties 있으면 `signingConfig = signingConfigs.getByName("release")`(없으면 미지정=unsigned).
- `app/proguard-rules.pro` 신설: kotlinx-serialization + LiteRT-LM keep.

| 파일 | 변경 |
|---|---|
| `app/build.gradle.kts` | keystore.properties 로드, signingConfigs.release(조건부), release minify+shrinkResources+signingConfig |
| `app/proguard-rules.pro` | 신설 — keep 규칙 |
| `.gitignore` | `keystore.properties` 추가 |
| (문서) | keystore 생성·주입 가이드(README 또는 spec 참고 섹션) |

## Components

### signing 골격 (build.gradle.kts)
```kotlin
import java.util.Properties

val keystoreProps = Properties().apply {
    val f = rootProject.file("keystore.properties")
    if (f.exists()) f.inputStream().use { load(it) }
}

android {
    signingConfigs {
        if (keystoreProps.getProperty("storeFile") != null) {
            create("release") {
                storeFile = file(keystoreProps.getProperty("storeFile"))
                storePassword = keystoreProps.getProperty("storePassword")
                keyAlias = keystoreProps.getProperty("keyAlias")
                keyPassword = keystoreProps.getProperty("keyPassword")
            }
        }
    }
    buildTypes {
        release {
            isMinifyEnabled = true
            isShrinkResources = true
            proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")
            if (keystoreProps.getProperty("storeFile") != null) {
                signingConfig = signingConfigs.getByName("release")
            }
        }
    }
}
```
> `keystore.properties` 부재 시 signingConfigs.release를 만들지 않고 release buildType에도 미지정 → release APK는 **unsigned**로 빌드 성공(시크릿 없는 환경/CI 보호). 실제 출시 시 사용자가 keystore.properties 작성.

### `app/proguard-rules.pro` (keep 규칙)
```
# kotlinx.serialization — @Serializable 생성 serializer 보존
-keepattributes *Annotation*, InnerClasses
-dontnote kotlinx.serialization.**
-keepclassmembers class **$$serializer { *; }
-keepclasseswithmembers class * { @kotlinx.serialization.Serializable <methods>; }
-keep,includedescriptorclasses class com.just.**$$serializer { *; }
-keepclassmembers class com.just.** {
    *** Companion;
}
-keepclasseswithmembers class com.just.** {
    kotlinx.serialization.KSerializer serializer(...);
}
# LiteRT-LM (JNI) 보존
-keep class com.google.ai.edge.litertlm.** { *; }
-keepclassmembers class com.google.ai.edge.litertlm.** { *; }
```
> Hilt/Room/Compose/Retrofit/OkHttp는 consumer 규칙 자동 적용 — 추가 keep 불필요.

### keystore.properties (사용자 작성, gitignored — 예시 문서화)
```
storeFile=/absolute/path/to/release.jks
storePassword=****
keyAlias=****

```

## Data Flow
빌드 타임만. `assembleRelease` → R8 축소 + (keystore 있으면)서명 → APK. 런타임 동작은 동일(축소된 코드).

## Error handling / 리스크
- keystore.properties 부재 → unsigned APK(빌드 성공). 문서로 안내.
- **R8 런타임 리스크**: 직렬화/JNI strip 시 크래시 가능 → 보수적 keep. 최종 정합성은 **실기기 smoke**로 확인(누적 QA). 문제 시 `app/build/outputs/mapping/release/mapping.txt`로 역추적.

## Testing
- `./gradlew :app:assembleRelease` — R8 축소·리소스 shrink·(unsigned)패키징 성공 확인. **빌드 자체가 keep 규칙 누락의 1차 검출**(missing class 경고).
- `./gradlew testDebugUnitTest` — 기존 단위 테스트(debug) PASS(무영향).
- ⚠️ 수동 smoke(실기기, release APK): 앱 실행·채팅·캡처·모델 다운로드·직렬화 경로(노트 저장/카탈로그 파싱)·LiteRT 추론이 R8 후에도 동작하는지. (기기 필요 — 누적 QA에 포함.)
