# v0.4.A — TTS 음성 응답 (채팅 답변 낭독)

**날짜:** 2026-06-08
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v0.4 대화형 채팅 (PR #11, feature/v0.4-plan)

## Goal

채팅 어시스턴트 응답을 **Android TextToSpeech로 소리내어 읽어준다** — 자비스형 비서의 "말하는 입". 상단바 토글로 켜면, 응답 스트리밍이 끝나는 순간 전체 텍스트를 낭독한다. STT 입력(이미 구현)과 합쳐 "말하고 듣는" 핸즈프리 대화의 기반.

## Background

- 메인 설계 문서가 TTS를 Android `TextToSpeech`로 예정해 둠("v0.1 옵셔널").
- v0.4 채팅은 어시스턴트 응답을 토큰 스트리밍으로 표시(`ChatViewModel`이 마지막 ASSISTANT 메시지에 델타 append, 완료 시 `isStreaming=false`).
- 자비스 북극성([[project-local-ai-assistant]])의 "말하는 입" 단계.

## Scope / 비목표

- 범위: 채팅 응답 낭독, 상단바 on/off 토글, 완료 시 낭독.
- 비목표: 문장 단위 스트리밍 낭독, 음성·속도·피치 선택 UI, Capture 화면 낭독, 다국어 음성 자동 전환.

## Architecture

| 모듈 | 변경 |
|---|---|
| `:local` (신규 `TtsSpeaker`) | Android `TextToSpeech` 래퍼. `@Singleton`(@ApplicationContext). `speak(text)`/`stop()`. 비동기 init, 시스템 기본 로케일, `QUEUE_FLUSH`. `LocalModule`에 `@Provides` |
| `feature_chat/ChatViewModel` | `TtsSpeaker` 주입. `ChatState.ttsEnabled`. `onToggleTts()`. 스트리밍 정상 완료 시 낭독. send/cancel/reset/onCleared에서 stop |
| `feature_chat/ChatScreen` | 상단바 음성 출력 토글 버튼 + strings |
| `feature_chat/build.gradle.kts` | `implementation(project(":local"))` 추가 |

추가 의존성·권한 없음(TextToSpeech는 권한 불필요).

## Components

### `:local/audio/TtsSpeaker`

```kotlin
interface TtsSpeaker {
    /** [text]를 낭독. 이전 발화는 끊고 새로 시작(QUEUE_FLUSH). 미초기화/실패 시 no-op. */
    fun speak(text: String)
    /** 현재 낭독 중단. */
    fun stop()
}

@Singleton
class TtsSpeakerImpl
    @Inject
    constructor(
        @ApplicationContext context: Context,
    ) : TtsSpeaker {
        @Volatile private var ready = false
        private lateinit var tts: TextToSpeech

        init {
            tts =
                TextToSpeech(context) { status ->
                    if (status == TextToSpeech.SUCCESS) {
                        tts.language = java.util.Locale.getDefault()
                        ready = true
                    }
                }
        }

        override fun speak(text: String) {
            if (!ready || text.isBlank()) return
            tts.speak(text, TextToSpeech.QUEUE_FLUSH, null, "chat")
        }

        override fun stop() {
            if (ready) tts.stop()
        }
    }
```

> `lateinit var tts`를 `init {}`에서 대입하고, onInit 콜백은 init 완료 후 비동기 호출되므로 콜백 내 `tts` 접근이 안전(자기참조 컴파일 이슈 회피). 앱 스코프 싱글톤(AlarmScheduler/ImageStore류와 동일 수명). `shutdown()`은 명시 호출 안 함(프로세스 종료 시 OS 회수) — MVP 허용. init 전 `speak`는 `ready=false`로 no-op(토글~첫 응답 사이 보통 준비됨).

### `feature_chat/ChatViewModel`

`ChatState`에 추가:
```kotlin
    val ttsEnabled: Boolean = false,
```

생성자에 `TtsSpeaker` 추가:
```kotlin
@HiltViewModel
class ChatViewModel @Inject constructor(
    private val startChatSession: StartChatSessionUseCase,
    private val tts: TtsSpeaker,
) : ViewModel() { ... }
```

동작:
- `onToggleTts()`: `ttsEnabled` 반전. 끄면 `tts.stop()`.
  ```kotlin
  fun onToggleTts() {
      val newValue = !_state.value.ttsEnabled
      if (!newValue) tts.stop()
      _state.update { it.copy(ttsEnabled = newValue) }
  }
  ```
- `onSend()`: 새 전송 시작 시 `tts.stop()`(이전 낭독 중단). 스트리밍 collect가 **정상 완료**되면(예외/취소 아님) 그 시점 `ttsEnabled`면 최종 어시스턴트 텍스트를 낭독:
  ```kotlin
  // collect 직후, catch 이전이 아니라 — try 블록 끝(정상 완료)에서:
  s.send(text).collect { delta -> /* append */ }
  // collect 정상 종료 후:
  if (_state.value.ttsEnabled) {
      val finalText = _state.value.messages.lastOrNull()?.text.orEmpty()
      if (finalText.isNotBlank()) tts.speak(finalText)
  }
  ```
  (취소 시 `streamJob.cancel`로 collect가 CancellationException → speak 도달 안 함. 에러 시 catch로 빠져 speak 도달 안 함.)
- `onCancel()`: 기존 동작 + `tts.stop()`.
- `onResetConversation()`: 기존 + `tts.stop()`.
- `onCleared()`: 기존 session.close + `tts.stop()`.

### `feature_chat/ChatScreen`

상단바 actions에 음성 토글 추가(기존 "새 대화" 옆):
```kotlin
                actions = {
                    TextButton(onClick = viewModel::onToggleTts) {
                        Text(
                            stringResource(
                                if (state.ttsEnabled) R.string.chat_tts_on else R.string.chat_tts_off,
                            ),
                        )
                    }
                    TextButton(onClick = viewModel::onResetConversation) {
                        Text(stringResource(R.string.chat_new))
                    }
                },
```

strings:
```xml
    <string name="chat_tts_on">음성 끄기</string>
    <string name="chat_tts_off">음성 켜기</string>
```

## Data Flow

```
[채팅 상단바] 음성 토글 → onToggleTts → ttsEnabled=true
사용자 전송 → onSend → tts.stop() (이전 낭독 중단)
  → session.send 스트리밍 → 마지막 ASSISTANT 버블 갱신
  → collect 정상 완료 → ttsEnabled면 tts.speak(최종 텍스트)
취소/새 대화/화면 종료 → tts.stop()
```

## Error handling

- TTS init 실패/엔진 미설치 → `ready=false` → `speak` no-op(조용히 무시, 토글은 켜지나 소리 없음).
- 빈/공백 응답 → speak 안 함.
- init 전 첫 speak → no-op(손실 허용; 토글~첫 응답 사이 보통 준비됨).

## Testing

### Unit (`feature_chat`, 기존 ChatViewModelTest 확장)
- Fake `TtsSpeaker`(speak/stop 호출 기록):
  - ttsEnabled=true + 스트리밍 완료 → `speak(최종 텍스트)` 1회.
  - ttsEnabled=false → speak 미호출.
  - `onSend` 시작 시 stop 호출(이전 낭독 중단) — 기록 확인.
  - `onToggleTts`로 끄면 stop 호출, 상태 반전.
  - 에러 경로(send throw) → speak 미호출.
- 기존 ChatViewModel 생성자 변경(+TtsSpeaker)에 맞춰 기존 4 테스트의 VM 생성에 Fake TtsSpeaker 인자 추가.

### `:local`
- `TtsSpeaker`는 Android `TextToSpeech` 직접 의존이라 단위 테스트 부적합 → 인터페이스+Fake로 VM 검증, 실엔진은 디바이스 smoke.

### 디바이스 smoke
1. 음성 토글 ON → 메시지 전송 → 응답 스트리밍 종료 후 한국어로 낭독.
2. 낭독 중 새 메시지 전송 → 이전 낭독 끊기고 진행.
3. 토글 OFF → 낭독 안 함.
4. 화면 나갔다 복귀 → 잔여 낭독 없음.
