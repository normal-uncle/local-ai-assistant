# v0.4 — 대화형 채팅 (순수 멀티턴, 스트리밍)

**날짜:** 2026-06-08
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v0.3.A~E (PR #6~#10) 모두 master merged

## Goal

단발 캡처·분류를 넘어 **주고받는 멀티턴 대화**를 도입한다. 사용자가 LLM과 채팅하고, 응답은 **토큰 스트리밍**으로 실시간 표시된다. 대화 기록은 **세션 내 메모리**에만 유지(앱 종료 시 초기화). 이는 [[project-local-ai-assistant]]의 북극성(자비스형 비서)으로 가는 첫걸음 — "대화하는 뇌".

**비목표(이번):** 메모/일정 인지(RAG), 행동(tool use), 음성 응답(TTS), 기록 영구저장. 순수 대화의 핵심 난제(멀티턴 컨텍스트·온디바이스 지연·스트리밍)를 먼저 검증한다.

## Background

- 현재 `InferenceEngine`은 **stateless** — `generate`마다 `Conversation`을 만들고 닫아 멀티턴 기억이 없다. 채팅엔 턴 간 컨텍스트 유지가 필요.
- LiteRT-LM 0.12.0 `Conversation`은 **네이티브 멀티턴**을 지원: 한 `Conversation` 객체에 `sendMessage`/`sendMessageAsync`를 반복하면 KV 캐시로 이전 맥락을 유지한다. `sendMessageAsync(String): Flow<Message>`로 **스트리밍** 가능.
- 온디바이스 제약: `maxNumTokens=4096` 고정([[project-litertlm-gemma4-config]]), 분류 기준 p50 ~14s(SD8G1 CPU). 멀티턴 누적은 4096을 빠르게 소진하고 턴마다 지연이 큼 → 스트리밍 UX + 4096 초과 처리가 필수.
- 내비: `AssistantRoute`(Onboarding/Capture/Memo) + Navigation3 `NavDisplay`. feature는 `feature_capture`/`feature_memo`/`feature_onboarding` 모듈로 분리, `:app`이 Scene을 entry로 연결.

## Architecture

핵심 결정: **SDK `Conversation`을 세션 동안 열어두고 재사용**(안 A). `ChatSession`이 `Conversation` 하나를 보유하고 턴마다 `sendMessageAsync`. KV 캐시로 멀티턴 컨텍스트가 자동 유지되어 히스토리 재prefill이 없다.

| 모듈 | 변경 |
|---|---|
| `:ai` | `InferenceEngine.startChat(): ChatSession` 추가. `ChatSession`(`send(message): Flow<String>`, `close()`) 인터페이스 + LiteRtLm 구현(`Conversation` 보관 + `sendMessageAsync` → 텍스트 델타 Flow) |
| `:usecase` | `StartChatSessionUseCase` 신설 + `@Binds` — 모델 준비 보장 후 `ChatSession?` 반환 |
| `feature_chat` (신규) | `ChatScene`/`ChatScreen`/`ChatViewModel` + `ChatMessage` UI 모델 + strings |
| `:app` | `AssistantRoute.Chat` 추가, `AssistantApp` NavDisplay에 entry, `CaptureScene`에 채팅 열기 콜백 배선 |
| `feature_capture` | `CaptureScene`/`CaptureScreen` 상단바에 "채팅" 버튼 + `onOpenChat` 콜백(파라미터 추가) |

추가 의존성·권한 없음. DB·모델 변경 없음.

## Components

### `:ai/ChatSession` + `InferenceEngine.startChat`

```kotlin
interface ChatSession {
    /** 사용자 메시지 전송 → 응답 토큰 델타 스트림. 마지막에 자연 종료. */
    fun send(message: String): kotlinx.coroutines.flow.Flow<String>
    /** 세션 종료(Conversation 닫기). 이후 send는 IllegalStateException. */
    fun close()
}

interface InferenceEngine {
    // ... 기존 load/unload/isReady/generate(...)/lastBackend ...
    /**
     * 멀티턴 채팅 세션 시작. 호출 전 [load] 필요.
     * 기본 구현은 미지원 throw — 채팅을 지원하는 엔진(LiteRtLm)만 override한다.
     * (분류 전용 테스트 Fake 등은 override 불필요.)
     */
    fun startChat(): ChatSession = throw UnsupportedOperationException("chat not supported")
}
```

> `startChat`을 default(throw)로 두어 인터페이스 확장이 기존 `generate`-only FakeEngine(ClassifyCapture/ClassifyImage 테스트)을 깨지 않게 한다. 실제 구현은 `LiteRtLmInferenceEngine`, 그리고 `StartChatSessionUseCaseImplTest`의 Fake 엔진만 override한다.

### `:ai/LiteRtLmInferenceEngine` 구현

```kotlin
override fun startChat(): ChatSession {
    val e = engine ?: error("InferenceEngine not loaded; call load() first")
    val cfg = currentConfig ?: error("InferenceEngine not loaded; call load() first")
    val samplerConfig = SamplerConfig(
        topK = cfg.topK, topP = cfg.topP.toDouble(),
        temperature = cfg.temperature.toDouble(), seed = 0,
    )
    val conversation = e.createConversation(
        ConversationConfig(
            systemInstruction = null,
            initialMessages = emptyList(),
            tools = emptyList(),
            samplerConfig = samplerConfig,
        ),
    )
    return LiteRtLmChatSession(conversation)
}

private class LiteRtLmChatSession(
    private val conversation: com.google.ai.edge.litertlm.Conversation,
) : ChatSession {
    override fun send(message: String): Flow<String> =
        conversation.sendMessageAsync(message)   // Flow<Message>
            .map { msg ->
                msg.contents.contents
                    .filterIsInstance<Content.Text>()
                    .joinToString("") { it.text }
            }
            .flowOn(Dispatchers.IO)
    override fun close() = conversation.close()
}
```

> `sendMessageAsync(String): Flow<Message>` 가 누적 텍스트를 emit하는지 델타를 emit하는지는 SDK 동작에 따른다. ChatViewModel은 **마지막 emit 값으로 진행 중 메시지를 교체**(set, not append)하는 방식으로 양쪽 모두 안전하게 처리한다(plan에서 확정). 텍스트 추출은 기존 `generate`와 동일 패턴.

### `:usecase/StartChatSessionUseCase`

```kotlin
interface StartChatSessionUseCase {
    /** 모델 준비 시 ChatSession, 미준비 시 null. */
    suspend operator fun invoke(): ChatSession?
}

class StartChatSessionUseCaseImpl @Inject constructor(
    private val engine: InferenceEngine,
    private val fileStore: ModelFileStore,
    private val prefs: ModelStatusPrefs,
) : StartChatSessionUseCase {
    override suspend fun invoke(): ChatSession? {
        val variantId = prefs.selectedVariantId.first() ?: return null
        val modelFile = fileStore.fileFor(variantId).takeIf { it.exists() } ?: return null
        return try {
            if (!engine.isReady()) engine.load(modelFile, InferenceConfig())
            engine.startChat()
        } catch (t: Throwable) {
            null
        }
    }
}
```

`UseCaseModule`에 `@Binds`. 모델 로딩 로직은 기존 `ClassifyCaptureUseCaseImpl` 미러(텍스트 config, vision/audio off).

### `feature_chat/ChatViewModel`

```kotlin
data class ChatMessage(val role: Role, val text: String) { enum class Role { USER, ASSISTANT } }

data class ChatState(
    val messages: List<ChatMessage> = emptyList(),
    val input: String = "",
    val isStreaming: Boolean = false,
    val error: String? = null,
    val modelReady: Boolean = true,
)

@HiltViewModel
class ChatViewModel @Inject constructor(
    private val startChatSession: StartChatSessionUseCase,
) : ViewModel() {
    private var session: ChatSession? = null
    private var streamJob: Job? = null
    // state: MutableStateFlow<ChatState>

    fun onInputChanged(text: String) { /* update input */ }

    fun onSend() {
        val text = state.value.input.trim()
        if (text.isEmpty() || state.value.isStreaming) return
        viewModelScope.launch {
            val s = session ?: startChatSession()?.also { session = it }
            if (s == null) { /* modelReady=false, error 안내 */ return@launch }
            // USER 메시지 + 빈 ASSISTANT 메시지 추가, input 비움, isStreaming=true
            streamJob = launch {
                try {
                    s.send(text).collect { partial ->
                        // 진행 중 ASSISTANT 메시지 텍스트를 partial로 set(교체)
                    }
                } catch (t: Throwable) {
                    // 4096 초과/추론 실패 → error 안내 + 세션 리셋(session.close(); session=null)
                } finally { /* isStreaming=false */ }
            }
        }
    }

    fun onCancel() { streamJob?.cancel() /* isStreaming=false, 부분 텍스트 유지 */ }
    fun onResetConversation() { session?.close(); session = null; /* messages 비움 */ }
    override fun onCleared() { session?.close() }
}
```

### `feature_chat/ChatScreen`
- 상단바(제목 + "새 대화" 액션 → `onResetConversation`).
- 메시지 `LazyColumn`(USER 우측/ASSISTANT 좌측 정렬, 간단 버블). 스트리밍 중 마지막 ASSISTANT 버블이 실시간 갱신.
- 하단 입력창 + 전송 버튼. `isStreaming`이면 전송 버튼이 **취소** 버튼으로 전환(`onCancel`).
- `modelReady == false`면 "모델 준비 중" 배너.

### `:app` / `feature_capture` 내비
- `AssistantRoute`에 `@Serializable data object Chat : AssistantRoute`.
- `AssistantApp`의 `entryProvider`에 `entry<AssistantRoute.Chat> { ChatScene(onBack = { backStack.removeLastOrNull() }) }`.
- `CaptureScene(onOpenMemo, onOpenChat)` — `onOpenChat` 파라미터 추가. `CaptureScreen` 상단바 actions에 "채팅" 버튼(기존 "목록" 버튼 옆). `AssistantApp`에서 `onOpenChat = { backStack.add(AssistantRoute.Chat) }`.

## Data Flow

```
[Capture 상단바] "채팅" → AssistantRoute.Chat → ChatScene/ChatScreen
사용자 입력 → onSend
  → (최초) StartChatSessionUseCase: 모델 load + engine.startChat() → ChatSession 보관
  → USER 메시지 + 빈 ASSISTANT 메시지 추가
  → session.send(text): Flow<String> 수집 → ASSISTANT 메시지 실시간 갱신(스트리밍)
  → 완료 시 isStreaming=false
다음 턴 → 같은 session.send(...) (Conversation KV 캐시로 이전 맥락 유지)
취소 → streamJob.cancel (부분 응답 유지)
4096 초과/실패 → error 안내 + "새 대화"로 세션 리셋
```

## Error handling
- 모델 미준비(변종 미선택/파일 없음) → `StartChatSessionUseCase` null → `modelReady=false` 배너(온보딩 유도).
- 추론 실패 / **4096 토큰 초과**(누적 컨텍스트 한계) → `send` Flow throw → 에러 메시지 버블 + "새 대화 시작" 안내, `session.close()` 후 `session=null`.
- 취소 → 진행 중 응답 중단, 그때까지 부분 텍스트 유지.
- 빈 입력/스트리밍 중 전송 → no-op(가드).
- `onCleared`에서 세션 close(리소스 누수 방지).
