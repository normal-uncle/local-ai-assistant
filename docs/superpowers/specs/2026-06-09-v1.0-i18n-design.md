# v1.0-i18n — 다국어 (한·영)

**날짜:** 2026-06-09
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v0.6까지 master merged. (v1.0 출시 준비 sub-project 1/N)

## Goal

앱 UI를 **한국어·영어** 양쪽으로 표시한다. 영어 로케일 기기는 영어, 그 외(한국어 포함)는 한국어. 설계 문서 v1.0 로드맵의 다국어 항목 첫 단계. Play Store 한·미 시장 대비.

## Scope / 비목표

- **범위:** 7개 모듈 전체에 `values-en/strings.xml` 추가(현 ~89개 문자열의 영어 번역). 기본(`values/`)은 한국어 유지. UI 하드코딩 한글 2곳 정리. app `resourceConfigurations` 제한.
- **비목표:** AI 프롬프트/RAG 라벨 번역(모델 입력 — 분류 정확도 영향, 별도 과제), 영어 외 추가 언어, 인앱 언어 선택기(시스템 로케일 따름), 날짜/숫자 포맷 커스텀(이미 시스템 로케일 포맷터 사용).

## Background

- 모든 문자열이 `values/`(한국어)에 있고 `values-en` 없음 → 영어 기기도 한국어로 표시됨.
- 모듈: `app`(1) `feature_capture`(40) `feature_chat`(12) `feature_memo`(18) `feature_onboarding`(9) `feature_settings`(3) `local`(6). 총 89.
- 프로젝트가 strings.xml 규칙을 지켜와 UI 하드코딩 한글은 거의 없음. 감사 결과 UI 폴백 2곳만 잔존:
  - `OnboardingScreen.kt`: `stringResource(R.string.onboarding_error, "다운로드 실패")` — 폴백 인자가 하드코딩.
  - `CaptureViewModel.kt`: `error = e.message ?: "저장 실패"` — 저장 실패 폴백(ViewModel, Context 없음).
- AI 프롬프트(`ClassificationPrompt` 등)·RAG 라벨(`RetrieveNoteContextUseCaseImpl`의 "메모/일정/리마인더")·채팅 증강 프롬프트는 **모델 입력**이라 UI 번역 대상 아님 — 한국어 유지.

## Architecture / 접근

각 모듈에 `src/main/res/values-en/strings.xml`을 만들고 `values/`와 **동일한 string name 집합**을 영어로 채운다. Android 리소스 시스템이 기기 로케일에 맞춰 자동 선택, 미존재 시 `values/`(한국어) 폴백.

| 모듈 | 추가 |
|---|---|
| app/feature_capture/feature_chat/feature_memo/feature_onboarding/feature_settings/local | `values-en/strings.xml` (모듈별 영어 번역) |
| app | `defaultConfig { resourceConfigurations += listOf("en", "ko") }` (라이브러리 locale 번들 축소) |
| feature_onboarding | `OnboardingScreen` 폴백을 `R.string.onboarding_error_generic`로(신규 string, 한·영) |
| feature_capture | `CaptureViewModel`은 `error = e.message`만(한글 폴백 제거); `CaptureScreen`이 error 표시 시 `state.error ?: stringResource(R.string.capture_save_failed)`(신규 string, 한·영)로 localized 폴백 |

### 번역 원칙
- string name·포맷 인자(`%1$d`, `%2$s`, `%%`) **완전 동일**. 누락/오타 시 빌드 또는 런타임 폴백 문제.
- 자연스러운 영어(직역 지양). 예: `capture_top_title` "새 메모" → "New note", `capture_preparing` "AI 분석 중…" → "Analyzing…", `briefing_title` "오늘 일정 %1$d건" → "%1$d events today", `briefing_more` "…외 %1$d건" → "…and %1$d more".
- 신규 string도 양쪽(values/values-en)에 추가: `onboarding_error_generic`(다운로드 실패/Download failed), `capture_save_failed`(저장 실패/Failed to save).

## Components (모듈별 values-en — 전체 번역은 plan에)

plan이 7개 `values-en/strings.xml` 전체 내용(영어)을 명시한다. 각 파일은 대응 `values/`의 모든 name을 1:1 포함.

신규 string 2개(양쪽 추가):
- `feature_onboarding`: `onboarding_error_generic` = 다운로드 실패 / Download failed
- `feature_capture`: `capture_save_failed` = 저장 실패 / Failed to save

## Data Flow
런타임 동작: Android가 `Resources.getString`/`stringResource` 호출 시 기기 로케일로 `values-en`(en) 또는 `values`(ko/기타) 선택. 코드 변경 없음(이미 모든 UI가 `stringResource`/`getString`).

## Error handling
- 번역 누락 string → 한국어(`values/`) 폴백(앱 동작 유지, 일부 한국어 노출). lint MissingTranslation로 사전 점검.
- 포맷 인자 불일치 → 런타임 포맷 예외 가능 → plan/검증에서 인자 동일성 확인.

## Testing
- **빌드:** `./gradlew :app:assembleDebug` + 전 모듈 컴파일.
- **lint(권장):** `./gradlew :app:lintDebug` 또는 `lint`로 `MissingTranslation`/`ExtraTranslation` 0 확인(가능 범위; 시간 길면 모듈별 strings name diff 스크립트로 1:1 검증).
- **name 일치 검증:** 각 모듈 `values` vs `values-en`의 `<string name=...>` 집합이 동일한지(추가 신규 2개 포함) 확인.
- **디바이스 수동 smoke:** 에뮬레이터/기기 언어를 English로 바꿔 앱 주요 화면(Capture/Memo/Chat/Settings/Onboarding/알림)이 영어로 표시되는지, 한국어로 되돌리면 한국어인지 확인.
- 단위 테스트 영향 없음(문자열 리소스만 추가).
