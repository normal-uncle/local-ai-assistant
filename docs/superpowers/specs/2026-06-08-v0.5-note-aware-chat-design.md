# v0.5 — 메모/일정 인지 채팅 (경량 RAG)

**날짜:** 2026-06-08
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v0.4 채팅 + v0.4.A TTS (PR #11/#12, master merged)

## Goal

채팅이 사용자의 **저장된 메모·일정을 근거로** 답하게 한다. 메시지를 보낼 때 관련 있는 노트만 골라 프롬프트에 끼워 넣어, "내일 일정 뭐 있어?" 같은 질문에 실제 데이터로 응답한다. **임베딩 없이**(키워드+다가오는 일정 휴리스틱) 온디바이스 4096 토큰 예산 안에서 동작. 자비스 북극성([[project-local-ai-assistant]])의 "내 데이터를 아는 비서" 단계.

**비목표:** 벡터/의미 검색(임베딩, sqlite-vec), 노트 전체 인덱싱, 대화 중 노트 생성·수정(tool use), 컨텍스트 요약 압축. (원설계 v0.5의 벡터 RAG는 후속으로 미룸.)

## Background

- v0.4 채팅은 순수 멀티턴(저장 데이터 접근 없음). `ChatViewModel(startChatSession, tts)` → `ChatSession.send(message): Flow<String>` 스트리밍. USER/ASSISTANT 메시지를 `messages`에 보관.
- 저장 데이터: `NoteRepository.observeAll(): Flow<List<Note>>`. `Note(title, body, type: NoteType{MEMO,EVENT,REMINDER}, datetime: Instant?, ...)`.
- `() -> Instant` clock이 DI로 제공됨(`provideClock`). 휴리스틱의 "현재 시각" 주입에 사용.
- 4096 토큰 고정([[project-litertlm-gemma4-config]]) — 주입 컨텍스트는 상한을 둬야 함.

## Architecture

핵심: 메시지 전송 시 `RetrieveNoteContextUseCase(query)`로 관련 노트를 짧은 텍스트 블록으로 만들고, **모델에 보내는 메시지에만** 끼워 넣는다. UI 말풍선엔 원래 사용자 텍스트만 보인다(표시용/전송용 분리).

| 모듈 | 변경 |
|---|---|
| `:usecase` | `RetrieveNoteContextUseCase` 신설(`NoteRepository` + `() -> Instant` clock) + `@Binds` |
| `feature_chat` | `ChatViewModel`에 `RetrieveNoteContextUseCase` 주입(3번째 ctor 파라미터). `onSend`에서 컨텍스트 검색 후 전송 메시지 증강, 말풍선은 원문. 테스트 갱신 |
| 그 외 | 모델·DB·UI 레이아웃·`:ai` 변경 없음 |

`feature_chat`는 이미 `:usecase`/`:repository` 의존. 추가 의존성·권한 없음.

## Components

### `:usecase/RetrieveNoteContextUseCase`

```kotlin
interface RetrieveNoteContextUseCase {
    /** [query]와 관련된 저장 노트를 짧은 텍스트 블록으로. 관련 없으면 "". */
    suspend operator fun invoke(query: String): String
}
```

구현(`RetrieveNoteContextUseCaseImpl`, `@Inject` NoteRepository + `clock: () -> Instant`):

1. `val notes = noteRepository.observeAll().first()`. 비면 "".
2. **다가오는 일정**: `datetime != null && datetime >= now` 인 노트를 datetime 오름차순, 최대 `MAX_UPCOMING=5`.
3. **키워드 매칭**: query를 소문자화→공백 분리→길이 2+ 토큰. 각 노트 점수 = (title+body 소문자에 등장하는 토큰 종류 수). 점수>0 내림차순, 다가오는 일정과 중복 제외, 최대 `MAX_KEYWORD=5`.
4. 합친 목록을 항목당 한 줄로 포맷:
   - `- [유형] 제목 (yyyy-MM-dd HH:mm if datetime) : 본문(최대 60자, 줄바꿈 공백 치환)`
   - 유형 한글 라벨(메모/일정/리마인더).
5. 전체를 `MAX_CHARS=1000` 으로 자른다(초과 시 마지막 완성 줄까지).
6. 결과 비면 "", 아니면 그대로 반환(헤더는 ViewModel이 붙임).

```kotlin
class RetrieveNoteContextUseCaseImpl @Inject constructor(
    private val noteRepository: NoteRepository,
    private val clock: () -> Instant,
) : RetrieveNoteContextUseCase {
    override suspend fun invoke(query: String): String {
        val notes = noteRepository.observeAll().first()
        if (notes.isEmpty()) return ""
        val now = clock()
        val upcoming = notes
            .filter { it.datetime != null && !it.datetime!!.isBefore(now) }
            .sortedBy { it.datetime }
            .take(MAX_UPCOMING)
        val tokens = query.lowercase().split(Regex("\\s+")).filter { it.length >= 2 }
        val keyword = notes
            .filter { it !in upcoming }
            .map { note ->
                val hay = (note.title + " " + note.body).lowercase()
                note to tokens.count { hay.contains(it) }
            }
            .filter { it.second > 0 }
            .sortedByDescending { it.second }
            .take(MAX_KEYWORD)
            .map { it.first }
        val selected = upcoming + keyword
        if (selected.isEmpty()) return ""
        val lines = selected.joinToString("\n") { formatLine(it) }
        return if (lines.length <= MAX_CHARS) lines
        else lines.substring(0, MAX_CHARS).substringBeforeLast("\n")
    }

    private fun formatLine(note: Note): String { /* "- [라벨] 제목 (시각) : 본문60자" */ }

    companion object {
        const val MAX_UPCOMING = 5
        const val MAX_KEYWORD = 5
        const val MAX_CHARS = 1000
    }
}
```

`UseCaseModule`에 `@Binds`. `formatLine`의 날짜 포맷은 `DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm")` + 시스템 zone.

### `feature_chat/ChatViewModel` 변경

ctor에 추가(3번째):
```kotlin
    constructor(
        private val startChatSession: StartChatSessionUseCase,
        private val tts: TtsSpeaker,
        private val retrieveNoteContext: RetrieveNoteContextUseCase,
    ) : ViewModel() {
```

`onSend()`에서 — USER 말풍선은 **원문** `text`, 모델 전송은 **증강** 메시지. 세션 확보 후, 메시지 추가 전/후 흐름은 유지하되 `send`에 넘기는 인자를 분리:
```kotlin
            viewModelScope.launch {
                val s = session ?: startChatSession()?.also { session = it }
                if (s == null) { _state.update { it.copy(modelReady = false) }; return@launch }
                tts.stop()
                _state.update { /* USER(text) + ASSISTANT("") 추가, 기존과 동일 (text 원문) */ }
                val context = runCatching { retrieveNoteContext(text) }.getOrDefault("")
                val augmented =
                    if (context.isBlank()) text
                    else "[참고 정보 — 사용자의 저장된 메모·일정]\n$context\n\n[질문]\n$text"
                streamJob = launch {
                    try {
                        s.send(augmented).collect { delta -> /* 기존: 마지막 메시지에 append */ }
                        /* 기존: ttsEnabled면 speak */
                    } catch (...) { ... } finally { ... }
                }
            }
```
> 변경점은 (1) `retrieveNoteContext(text)` 호출, (2) `s.send(augmented)`로 전송(표시는 원문). 나머지(스트리밍/취소/에러/TTS)는 v0.4/v0.4.A 그대로.

## Data Flow

```
사용자 입력 "내일 일정 뭐 있어?" → onSend
  → USER 말풍선 = 원문 표시
  → RetrieveNoteContextUseCase("내일 일정 뭐 있어?")
      → observeAll 노트 → 다가오는 일정 + 키워드 매칭 → ~1000자 블록
  → augmented = "[참고 정보]\n- [일정] 치과 (2026-06-09 15:00) : ...\n\n[질문]\n내일 일정 뭐 있어?"
  → session.send(augmented) 스트리밍 → ASSISTANT 답변(일정 반영)
관련 노트 없음 → augmented = 원문(일반 채팅)
```

추가 권한 없음.

## Error handling
- 노트 조회 실패/예외 → `runCatching … getOrDefault("")` → 컨텍스트 없이 일반 전송.
- 관련 노트 없음 → "" → 원문 전송.
- 컨텍스트 + 질문 + 히스토리가 4096 초과 → 기존 채팅 에러 경로(에러 배너 + 새 대화 리셋).
