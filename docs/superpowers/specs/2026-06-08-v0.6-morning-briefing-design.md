# v0.6 — 능동적 비서: 아침 브리핑

**날짜:** 2026-06-08
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v0.4/v0.4.A/v0.5 (master merged)

## Goal

사용자가 먼저 묻지 않아도 매일 **아침 08:00에 오늘의 일정·리마인더를 요약한 알림**을 띄운다. 자비스 북극성([[project-local-ai-assistant]])의 "먼저 챙기는 비서"(능동성) 첫걸음. 내용은 **템플릿 기반**(LLM 미사용 — 백그라운드 발열·배터리·정지 리스크 회피). 기본 OFF, 설정 토글로 옵트인.

**비목표:** LLM 자연어 브리핑, 시간 사용자 설정, 위치/날씨 등 외부 소스, 시간 외 선제 리마인드, 다중 브리핑.

## Background

- v0.5까지 모든 동작은 사용자 트리거. 능동성은 새 축.
- 인프라 현황: 알림(`NotificationChannelInitializer`, `CHANNEL_REMINDERS`), AlarmManager(`AlarmScheduler`), DataStore(`UserPreferences`) 존재. **WorkManager는 카탈로그에 있으나 미사용**(`work-runtime`/`hilt-work`/`work-testing`). 설정 화면 없음.
- `NoteRepository.observeAll()` + `() -> Instant` clock으로 오늘 일정 조회 가능.

## Architecture

스케줄링은 **WorkManager 자기재예약 one-time work**: 재부팅에도 enqueue가 지속돼 boot receiver가 불필요하고(AlarmManager는 재부팅 시 소실→BootReceiver+수동 재예약 필요), 매일 08:00 부근에 1회 실행 후 다음 날 work를 다시 enqueue한다.

| 모듈 | 변경 |
|---|---|
| `:usecase` | `BuildDailyBriefingUseCase` 신설 — 오늘 일정/리마인더 → 브리핑 텍스트(없으면 null) |
| `:local` | `BriefingWorker`(CoroutineWorker, @HiltWorker), `BriefingScheduler`(enable/disable, WorkManager). `NotificationChannelInitializer`에 `CHANNEL_BRIEFING` 추가. `UserPreferences`에 `briefingEnabled` |
| `feature_settings` (신규) | `SettingsScene`/`SettingsScreen`/`SettingsViewModel` — 브리핑 토글 |
| `:app` | `AssistantApplication` Hilt WorkManager 셋업(`Configuration.Provider`). `AssistantRoute.Settings` + NavDisplay entry + Capture 상단바 "설정" 진입. manifest WorkManager 기본 initializer 비활성(Hilt 통합 시 필요) |

추가 의존성: `work-runtime`/`hilt-work`(이미 카탈로그). 추가 권한 없음(POST_NOTIFICATIONS는 v0.3 보유).

## Components

### `:usecase/BuildDailyBriefingUseCase`

use case는 **구조화 데이터만** 반환하고, 사용자 노출 문구(고정 한글)는 Worker(:local, R.string 접근)가 조합한다 → [[feedback-string-resources]] 준수 + 테스트 용이.

```kotlin
interface BuildDailyBriefingUseCase {
    /** 오늘(로컬 자정~다음 자정) 일정·리마인더. 없으면 null. */
    suspend operator fun invoke(): DailyBriefing?
}

/** items 예: ["09:00 회의", "15:00 치과"] (시각+제목, 사용자 데이터). moreCount = MAX_ITEMS 초과분. */
data class DailyBriefing(val totalCount: Int, val items: List<String>, val moreCount: Int)
```

구현(`@Inject` NoteRepository + `clock: () -> Instant`):
1. `notes = observeAll().first()`.
2. 오늘 범위: datetime이 오늘(zone 기준)인 노트만, datetime 오름차순.
3. 없으면 null.
4. `items` = 상위 MAX_ITEMS를 `"HH:mm 제목"`으로, `totalCount` = 전체 수, `moreCount` = 초과분.

```kotlin
class BuildDailyBriefingUseCaseImpl @Inject constructor(
    private val noteRepository: NoteRepository,
    private val clock: () -> Instant,
) : BuildDailyBriefingUseCase {
    override suspend fun invoke(): DailyBriefing? {
        val zone = ZoneId.systemDefault()
        val today = clock().atZone(zone).toLocalDate()
        val todays = noteRepository.observeAll().first()
            .filter { it.datetime != null }
            .filter { it.datetime!!.atZone(zone).toLocalDate() == today }
            .sortedBy { it.datetime }
        if (todays.isEmpty()) return null
        val fmt = DateTimeFormatter.ofPattern("HH:mm")
        val shown = todays.take(MAX_ITEMS)
        val items = shown.map { "${fmt.format(it.datetime!!.atZone(zone))} ${it.title}" }
        return DailyBriefing(
            totalCount = todays.size,
            items = items,
            moreCount = todays.size - shown.size,
        )
    }
    companion object { const val MAX_ITEMS = 10 }
}
```
`UseCaseModule`에 `@Binds`. 알림 제목/본문 고정 문구("오늘 일정 %d건", "…외 %d건")는 **`:local` strings.xml**에서 Worker가 `getString(R.string.briefing_title, totalCount)` 등으로 조합.

### `:local/work/BriefingWorker`

```kotlin
@HiltWorker
class BriefingWorker @AssistedInject constructor(
    @Assisted appContext: Context,
    @Assisted params: WorkerParameters,
    private val buildBriefing: BuildDailyBriefingUseCase,
    private val scheduler: BriefingScheduler,
    private val prefs: UserPreferences,
) : CoroutineWorker(appContext, params) {
    override suspend fun doWork(): Result {
        try {
            if (prefs.briefingEnabled.first()) {
                buildBriefing()?.let { postBriefingNotification(applicationContext, it) }
            }
        } finally {
            if (prefs.briefingEnabled.first()) scheduler.scheduleNext()
        }
        return Result.success()
    }
}
```
- `postBriefingNotification(context, briefing: DailyBriefing)`: 제목=`getString(R.string.briefing_title, briefing.totalCount)`, 본문=`briefing.items.joinToString("\n")` + `if (moreCount>0) "\n" + getString(R.string.briefing_more, moreCount)`. `NotificationCompat`(CHANNEL_BRIEFING) + contentIntent → MainActivity 실행. AlarmReceiver 알림 빌더 패턴 참고.
- 토글 OFF면 알림 안 띄우고 재예약도 안 함(스케줄러 cancel은 토글에서 처리).

### `:local/work/BriefingScheduler`

```kotlin
@Singleton
class BriefingScheduler @Inject constructor(
    @ApplicationContext private val context: Context,
    private val clock: () -> Instant,
) {
    fun enable() { scheduleNext() }   // 다음 08:00 one-time work enqueue
    fun scheduleNext() {
        val delay = millisUntilNext(8, 0)  // 다음 08:00까지 ms (clock 기준)
        val req = OneTimeWorkRequestBuilder<BriefingWorker>()
            .setInitialDelay(delay, TimeUnit.MILLISECONDS)
            .build()
        WorkManager.getInstance(context)
            .enqueueUniqueWork(WORK_NAME, ExistingWorkPolicy.REPLACE, req)
    }
    fun disable() { WorkManager.getInstance(context).cancelUniqueWork(WORK_NAME) }
    companion object { const val WORK_NAME = "daily_briefing" }
}
```
- `millisUntilNext(8,0)`: clock 기준 오늘 08:00이 지났으면 내일 08:00, 아니면 오늘 08:00까지의 ms(테스트 가능한 순수 함수로 분리).
- `enqueueUniqueWork(REPLACE)`로 중복 방지. Worker가 끝에 `scheduleNext()`로 다음 날 재예약(자기재예약 체인). 재부팅 시 enqueue된 work가 WorkManager DB에 남아 실행됨.

## Data Flow

```
설정 화면 브리핑 토글 ON → prefs.setBriefingEnabled(true) + BriefingScheduler.enable()
  → WorkManager: 다음 08:00 one-time work enqueue (WORK_NAME 고유)
08:00(±deferrable) → BriefingWorker.doWork
  → briefingEnabled면 BuildDailyBriefingUseCase() → 오늘 일정 있으면 알림(CHANNEL_BRIEFING)
  → finally: 여전히 enabled면 scheduleNext() (다음 날)
재부팅 → enqueue된 work 유지 → 정상 실행
토글 OFF → prefs false + scheduler.disable()(cancelUniqueWork)
알림 탭 → MainActivity(앱) 실행
```

## Error handling
- 오늘 일정 없음 → 알림 스킵, 재예약 유지.
- Worker 예외 → `finally`에서 재예약 보장, `Result.success()`(재시도 폭주 방지).
- 토글 OFF 상태로 Worker 실행(레이스) → enabled 체크로 알림·재예약 모두 안 함.
- 알림 권한 없음 → NotificationManagerCompat가 무시(조용히).
