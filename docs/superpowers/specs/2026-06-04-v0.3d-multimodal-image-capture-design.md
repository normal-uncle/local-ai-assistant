# v0.3.D — 멀티모달 이미지 캡처 (사진 입력 → AI 분류)

**날짜:** 2026-06-04
**상태:** 디자인 승인됨 — spec 리뷰 대기
**선행:** v0.3.A (PR #6), v0.3.B (PR #7), v0.3.C (PR #8) — 모두 master merged

## Goal

원래 로드맵 v0.3의 핵심인 **이미지 입력**을 도입한다. 사용자가 카메라로 찍거나 갤러리에서 고른 사진(영수증·화이트보드·메모 사진 등)을 Gemma 멀티모달로 분류(MEMO/EVENT/REMINDER)하여 저장하고, 이미지를 Note에 첨부한다. 텍스트 캡션을 선택적으로 함께 보낼 수 있다.

## Background

- v0.1~v0.3.C는 텍스트(+STT) 입력만 다뤘다. `:ai`의 `InferenceEngine.generate(prompt: String)`는 텍스트 전용.
- LiteRT-LM 0.12.0 SDK는 멀티모달 입력을 지원함을 확인:
  - `Content.ImageBytes(ByteArray)`, `Content.ImageFile(absolutePath)`, `Content.Text(text)` 존재.
  - `Conversation.sendMessage(Contents)` 오버로드로 이미지+텍스트를 한 메시지에 실어 보낼 수 있음.
- **미확인 리스크:** 현재 카탈로그의 `gemma-4-E2B-it.litertlm` 변환본이 실제로 **vision 인코더 가중치를 포함**하는지는 별개 문제다. SDK API가 이미지를 받는 것과 모델이 vision을 실제로 추론하는 것은 다르다. 또한 메모리 기록상 이 모델은 `maxNumTokens=4096`에서만 동작했으며 이미지는 토큰을 크게 소모한다.
- 따라서 v0.3.D는 **feasibility spike를 첫 단계(gating)** 로 두고, 통과해야 본 구현을 진행한다.

## Architecture

핵심 아키텍처 결정: `InferenceEngine.generate`에 이미지 인자를 **기본값 오버로드**로 추가한다 (별도 메서드 신설이나 `CaptureInput` sealed 타입 도입 대신). 기존 텍스트 분류 경로를 건드리지 않는 최소 확장이며, v0.3.B에서 정착한 점진적 인터페이스 확장 패턴과 일치한다.

| 모듈 | 변경 |
|---|---|
| `:ai` | `InferenceEngine.generate(prompt, images: List<ByteArray> = emptyList())` 오버로드. `LiteRtLmInferenceEngine`이 images 비었으면 기존 경로, 있으면 `Contents=[ImageBytes…, Text]` 전송. `ImageClassificationPrompt` 신설 (이미지+선택 캡션 → 동일 JSON 스키마) |
| `:repository` | `Note` domain +`imageUri: String?`, mapper 양방향 |
| `:local` | `NoteEntity` v4 (+`imageUri: String?`), `MIGRATION_3_4`. `ImageStore` 신설 (다운스케일 + filesDir 복사) |
| `:usecase` | `ClassifyImageCaptureUseCase(imageBytes, caption?)` 신설 + Hilt `@Binds` |
| `:feature_capture` | 이미지 소스 버튼 2개 (PhotoPicker / TakePicture), 썸네일, 캡션 재사용, `onPrepareImage()`. PreviewSheet에 썸네일 표시. confirm 시 `ImageStore` 저장 + Note `imageUri` |
| `:feature_memo` | MemoDetail 첨부 이미지 썸네일, MemoList row 이미지 인디케이터 |
| `:app` | manifest `FileProvider` + `file_paths.xml`, `CAMERA` 권한 |

추가 의존성: Coil(이미지 로딩, Compose) 또는 표준 `BitmapFactory` + `Image` composable. **Coil 채택** — Compose 표준, 썸네일 캐싱/디코딩 처리. version catalog에 추가.

## Components

### `:ai/InferenceEngine` — 이미지 오버로드

```kotlin
interface InferenceEngine {
    suspend fun load(modelFile: File, config: InferenceConfig = InferenceConfig())
    fun unload()
    fun isReady(): Boolean

    /** 텍스트 전용 추론. images 비었을 때와 동일. */
    suspend fun generate(prompt: String): String =
        generate(prompt, emptyList())

    /** 멀티모달 추론. images 비었으면 텍스트 전용과 동일. */
    suspend fun generate(prompt: String, images: List<ByteArray>): String

    val lastBackend: String? get() = null
}
```

> 기존 `generate(prompt: String)` 호출부(텍스트 분류, 회귀 테스트)는 default 구현으로 무영향. Fake 엔진은 `generate(prompt, images)` 하나만 구현.

### `:ai/LiteRtLmInferenceEngine` — 멀티모달 전송

```kotlin
override suspend fun generate(prompt: String, images: List<ByteArray>): String =
    withContext(Dispatchers.IO) {
        val e = engine ?: error("InferenceEngine not loaded; call load() first")
        val cfg = currentConfig ?: error("InferenceEngine not loaded; call load() first")
        val samplerConfig = SamplerConfig(/* 기존과 동일 */)
        val conversationConfig = ConversationConfig(/* 기존과 동일 */)

        e.createConversation(conversationConfig).use { conversation ->
            val response =
                if (images.isEmpty()) {
                    conversation.sendMessage(prompt)
                } else {
                    val contents = Contents.of(
                        images.map { Content.ImageBytes(it) } + Content.Text(prompt),
                    )
                    conversation.sendMessage(contents)
                }
            response.contents.contents
                .filterIsInstance<Content.Text>()
                .joinToString(separator = "") { it.text }
        }
    }
```

> `Contents` 생성자는 private이며 companion factory `Contents.of(List<Content>)` / `Contents.of(vararg Content)`를 사용한다(SDK 0.12.0 확인됨). 이미지는 Text 앞에 배치 (모델이 이미지를 먼저 보고 지시를 읽도록).

### `:ai/ImageClassificationPrompt`

```kotlin
object ImageClassificationPrompt {
    fun build(caption: String?): String = """
        당신은 사용자가 첨부한 이미지를 분류하는 비서입니다.
        이미지(영수증·화이트보드·메모·일정표 등)를 읽고 정확히 하나의 JSON 객체로만 답하세요.

        JSON 스키마:
        { "type": "MEMO" | "EVENT" | "REMINDER",
          "title": "<짧은 제목, 최대 40자>",
          "body": "<이미지에서 읽은 핵심 내용>",
          "tags": ["<태그 0~3개>"],
          "datetime_iso": "<ISO 8601, 없으면 null>" }

        규칙:
        - 이미지에 날짜·시각이 있으면 EVENT, datetime_iso 채움.
        - 할 일/마감 성격이면 REMINDER.
        - 그 외는 MEMO. body에 이미지 핵심 텍스트 요약.
        ${caption?.takeIf { it.isNotBlank() }?.let { "\n사용자 메모: $it" } ?: ""}

        JSON:
    """.trimIndent()
}
```

기존 `ClassificationResult.parse` 재사용 (동일 스키마).

### `:local/image/ImageStore`

```kotlin
interface ImageStore {
    /** [source] uri의 이미지를 다운스케일 후 내부 저장소에 복사, 저장된 파일 uri 반환. */
    suspend fun persist(source: Uri): Uri
    /** 분류용 다운스케일 JPEG 바이트. (저장과 별개로 추론에만 쓰는 경량 변환) */
    suspend fun toClassifierBytes(source: Uri): ByteArray
}

@Singleton
class ImageStoreImpl @Inject constructor(
    @ApplicationContext private val context: Context,
) : ImageStore {
    // BitmapFactory inSampleSize로 최대 변 768px 디코드 → JPEG 85% 압축
    // persist: filesDir/images/<UUID>.jpg 에 write, FileProvider content uri 반환
    // toClassifierBytes: 동일 디코드 후 ByteArrayOutputStream
}
```

- 다운스케일 상한 **768px**(최대 변), JPEG 품질 **85%**. 토큰 예산(4096)과 OCR 가독성 절충.
- 저장 경로 `filesDir/images/` — 백업 제외(설계 3.5 정책 일관).

### `:usecase/ClassifyImageCaptureUseCase`

```kotlin
interface ClassifyImageCaptureUseCase {
    suspend operator fun invoke(imageBytes: ByteArray, caption: String?): ClassificationResult?
}

class ClassifyImageCaptureUseCaseImpl @Inject constructor(
    private val engine: InferenceEngine,
    private val fileStore: ModelFileStore,
    private val prefs: ModelStatusPrefs,
) : ClassifyImageCaptureUseCase {
    override suspend fun invoke(imageBytes: ByteArray, caption: String?): ClassificationResult? {
        val variantId = prefs.selectedVariantId.first() ?: return null
        val modelFile = fileStore.fileFor(variantId).takeIf { it.exists() } ?: return null
        return try {
            if (!engine.isReady()) engine.load(modelFile, InferenceConfig())
            val response = engine.generate(
                prompt = ImageClassificationPrompt.build(caption),
                images = listOf(imageBytes),
            )
            ClassificationResult.parse(response)
        } catch (t: Throwable) {
            null
        }
    }
}
```

`UseCaseModule`에 `@Binds`. 기존 `ClassifyCaptureUseCaseImpl` 미러 구조.

### `:feature_capture/CaptureScreen` + `CaptureViewModel`

UI 추가:

- 이미지 선택 상태에서 "준비" 버튼 → `onPrepareImage()`.

`CaptureViewModel`:
```kotlin
data class CaptureState(
    val input: String = "",
    val pickedImage: Uri? = null,
    val preview: CapturePreview? = null,
    val isPreparing: Boolean = false,
    val isSaving: Boolean = false,
    val error: String? = null,
)

fun onImagePicked(uri: Uri?) { _state.update { it.copy(pickedImage = uri) } }

fun onPrepareImage() {
    val uri = _state.value.pickedImage ?: return
    if (_state.value.isPreparing) return
    _state.update { it.copy(isPreparing = true) }
    viewModelScope.launch {
        val bytes = imageStore.toClassifierBytes(uri)
        val aiResult = classifyImage(bytes, _state.value.input.trim().ifEmpty { null })
        val preview = aiResult?.toPreview() ?: fallbackImagePreview()
        _state.update { it.copy(preview = preview, isPreparing = false) }
    }
}
```

confirm 시 (`onConfirm`): `pickedImage != null`이면 `imageStore.persist(uri)` → 저장된 uri를 Note `imageUri`에 실어 저장. EVENT/REMINDER 스케줄 로직은 기존과 동일.

ctor에 `ClassifyImageCaptureUseCase`, `ImageStore` 추가.

> `CapturePreview`/`Note`/`PreviewSheet`에 `imageUri` 전달 경로 추가. PreviewSheet는 imageUri 있으면 썸네일 표시.

## Data Flow

### 1. 갤러리/카메라 → 분류
```
[Capture 화면] 갤러리 버튼 → PhotoPicker → uri
            또는 카메라 버튼 → (CAMERA 권한) → TakePicture(FileProvider uri) → uri
  → viewModel.onImagePicked(uri) → 썸네일 표시
  → (선택) 캡션 입력
  → "준비" → onPrepareImage()
     → ImageStore.toClassifierBytes(uri)  [다운스케일 768px JPEG]
     → ClassifyImageCaptureUseCase(bytes, caption)
        → engine.generate(ImageClassificationPrompt.build(caption), [bytes])
        → ClassificationResult.parse(response)
     → PreviewSheet (분류 결과 + 썸네일, 사용자 수정 가능)
```

### 2. 확정 저장
```
PreviewSheet confirm
  → ImageStore.persist(pickedImage)  [filesDir/images/<uuid>.jpg, content uri]
  → SaveNote(note.copy(imageUri = persistedUri))
  → (EVENT/REMINDER면 기존 schedule 경로)
  → CaptureState 리셋
MemoDetail 방문 시 → 썸네일 표시
```

## Permissions

| 권한 | 용도 | 처리 |
|---|---|---|
| `CAMERA` | 카메라 촬영 | 카메라 버튼 탭 시 런타임 요청. 거부 시 "갤러리만 사용" 배너 + 설정 deeplink |
| (READ_MEDIA 불필요) | 갤러리 | PhotoPicker가 권한 없이 단건 선택 처리 |

기존 캘린더·알람·노티 권한 그대로.

## Error handling

- 모델 미준비/추론 실패/파싱 실패 → `ClassifyImageCaptureUseCase` null → MEMO 폴백(이미지 첨부는 유지, title=캡션 또는 "사진 메모").
- 카메라 권한 거부 → 갤러리만 안내 배너.
- 이미지 디코드 실패(손상/미지원 포맷) → toast + 캡처 취소, Note 저장 안 함.
- `ImageStore.persist` 실패(저장공간) → toast, 이미지 없이 텍스트만 저장 폴백.
- 큰 이미지 → 항상 768px 다운스케일이라 토큰 폭주 방지.
