# v0.3.B — GPU backend 시도 + ClassificationPrompt rules 강화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v0.2 baseline (typeAcc 0.72 / dtAcc 0.78 / p50 14.7s) 대비 (1) `Backend.GPU()` 시도 + 실패 시 자동 CPU fallback, (2) `ClassificationPrompt`의 rules 섹션에 동사형/시각 없는 일정 케이스 명시로 정확도 개선 시도.

**Tech Stack:** Kotlin, LiteRT-LM SDK 0.12.0 (`Backend.GPU()` / `Backend.CPU()`), JUnit4 + Robolectric (`:ai` unit tests), instrumented test (`:app/regression`).

- [ ] **Step 2: `load` 본문 교체 — GPU 시도 → CPU fallback + `_lastBackend` 설정**

`load` 함수의 본문을 다음으로 교체:

```kotlin
        override suspend fun load(
            modelFile: File,
            config: InferenceConfig,
        ) {
            withContext(Dispatchers.IO) {
                if (engine != null &&
                    currentConfig == config &&
                    currentModelPath == modelFile.absolutePath
                ) {
                    return@withContext
                }
                engine?.close()
                engine = null
                _lastBackend = null

                val baseConfig =
                    EngineConfig(
                        modelPath = modelFile.absolutePath,
                        backend = Backend.CPU(),
                        maxNumTokens = config.maxTokens,
                        cacheDir = context.cacheDir.absolutePath,
                    )

                val (newEngine, backend) =
                    try {
                        val gpu = Engine(baseConfig.copy(backend = Backend.GPU()))
                        gpu.initialize()
                        gpu to "GPU"
                    } catch (e: Throwable) {
                        Log.w(TAG, "GPU init failed, falling back to CPU", e)
                        val cpu = Engine(baseConfig.copy(backend = Backend.CPU()))
                        cpu.initialize()
                        cpu to "CPU(fallback)"
                    }

                engine = newEngine
                currentConfig = config
                currentModelPath = modelFile.absolutePath
                _lastBackend = backend
            }
        }
```

- [ ] **Step 2: Report 생성 시 `engine.lastBackend` 박기**

같은 파일에서 `val report = Report(...)` 형태로 보고서를 생성하는 부분을 찾아 한 필드 추가. 변경 후 (관련 줄만 수정):

```kotlin
            val report =
                Report(
                    variantId = variantId,
                    backend = engine.lastBackend ?: "unknown",
                    totalCases = results.size,
                    correctType = correctType,
                    accuracyType = correctType.toDouble() / results.size,
                    correctDatetime = correctDatetime,
                    accuracyDatetime = correctDatetime.toDouble() / results.size,

                    p95LatencyMs = p95,
```

> `engine.unload()`가 `_lastBackend = null` 처리하므로 (Task 1 Step 2 참조), Report 생성을 unload **전**에 해야 한다. 기존 코드에서 위치 확인 — 만약 unload가 Report 생성보다 앞에 있으면 순서를 바꿀 것. v0.2/v0.3.A 코드 기준으로 현재 순서는 `engine.unload()` 다음에 `val correctType ...` 계산, 그 다음 `val report = ...`. 즉 unload 후 report 생성. 이 task에선 다음과 같이 순서 조정:

```kotlin
            // unload 직전에 backend snapshot
            val backendUsed = engine.lastBackend ?: "unknown"
            engine.unload()

            // ... 기존 통계 계산 ...

            val report =
                Report(
                    variantId = variantId,
                    backend = backendUsed,
                    ...
                )
```

`backendUsed` local val을 unload 전에 만들고, Report에 그 값을 박는다.
